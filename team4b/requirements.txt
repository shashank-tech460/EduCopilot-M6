# pandas: not a direct dependency of ragas itself (verified: `pip show
# ragas` lists no pandas), but app/services/ragas_adapter.py imports it
# directly (`result.to_pandas()`, `pd.isna()`). It currently installs
# transitively via ragas -> datasets -> pandas, so a plain `pip install
# -r requirements.txt` already works today -- but relying on an
# incidental transitive dependency of a transitive dependency, for a
# package OUR OWN code imports directly, is a genuine build-
# reproducibility risk (Task 11.1): if a future ragas/datasets release
# drops that transitive chain, the build would still succeed but the
# application would fail at runtime with ModuleNotFoundError. Declared
# explicitly here, unpinned (matching every other unpinned entry in this
# file), so pip's resolver keeps picking whatever version is already
# compatible -- this is a declaration fix, not a version change.
pandas

# ragas==0.4.3 fails to import against the latest langchain-community
# (0.4.2) in this environment: ModuleNotFoundError for
# langchain_community.chat_models.vertexai. Pinned to the last known-
# compatible release (Task 9.1) -- the smallest change that fixes the
# import without touching any other already-approved dependency.
langchain-community<0.4
