## CRITICAL FINDING — Mongo database name mismatch in Team 4A's default

Direct source inspection of `app/config/settings.py` (Team 4A) vs.
`app/core/config.py` (Team 4B):

```
Team 4A: mongo_database_name default = "educopilot"          <-- WRONG for this integration
Team 4B: mongo_database_name default = "edu-copilot-team-c"  <-- matches Team 4C
```

Team 4A's Mongo authority client (`app/pipeline/mongo_authority.py`) writes
the ingestion-completion claim (`currentIngestionGeneration`, `ingestionId`)
onto the **same** `File` document Team 4C created and Team 4B later reads.
If Team 4A is started with its *default* database name, it will write to a
**different, wrong Mongo database** than the one Team 4C and Team 4B use —
Team 4C would never see the generation update, and ingestion would appear
to hang or silently not complete from the user's perspective, with no
error raised anywhere (both databases exist independently; nothing fails).

**Required local `.env` override for Team 4A (not optional, not one of
the defaults):**
```
MONGO_URL=mongodb://localhost:27017
MONGO_DATABASE_NAME=edu-copilot-team-c
```
This is a genuine, source-confirmed environment configuration requirement,
not a code defect — no source file needed to change to fix this, only the
local `.env`.
